# PRD Writing Patterns (Sanitized)

## 通用写法
- 先写业务背景和来源，再写用户场景，再写功能
- 优先用表格沉淀“要做什么、优先级、规则、边界”
- 对 AI 产品，功能详情中应显式写：上下文来源、输出边界、异常处理

## 可复用模式
### 优先级分层
- P0：首发必做，没有就无法上线
- P1：首发后应尽快补齐，缺失会明显影响完整性
- P2：中期增强，提升效率和体验
- P3：长期观察，价值不确定或非高频
- P4：明确不做，不符合定位或 ROI 不成立

### 页面逻辑 / 流程模式
- 适合在 3.x 子节中补充“页面逻辑”或“用户操作流程”
- 多步骤功能推荐用“入口 → 关键节点 → 结果”的顺序表达

### 多模块联动模式
- 需要写清楚：关联入口、关联状态、数据引用形式、限制条件
